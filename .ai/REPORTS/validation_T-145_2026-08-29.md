## Périmètre — ce qui est implémenté (et ce qui ne l'est pas, volontairement)

Implanté et testé dans ce lot :

1. **Photo de profil importée depuis le gestionnaire de fichiers** (voyageur et
   hôte).
2. **Commission plateforme par hébergement réglable par l'admin** dans
   l'interface (l'API l'acceptait déjà ; l'écran n'exposait pas le champ).
3. **Suppression de l'option de langue « arabe »** non supportée (incohérence
   UI).

Non implémenté volontairement (nécessite des ressources externes non
validables dans ce sandbox, donc pas simulé à blanc) :
- **Stripe Connect / versements bancaires hôtes** : intégration tierce à part
  entière (comptes connectés, external bank accounts, transfers) ; exige un
  compte Stripe et ne peut être prouvée sans clés.
- **Paiement carte réel** : le code (Stripe Elements + PaymentElement +
  webhook signé/idempotent) est présent et bascule automatiquement dès que les
  clés Stripe sont configurées ; la validation avec une vraie carte reste à
  faire côté prestataire.

## Détail des changements

### 1) Upload de photo de profil
- 🔨 Route **`POST /api/users/me/avatar`** (nouvelle) : utilisateur connecté
  (tous rôles), multipart champ `file` ; réutilise `getPublicUploader()` +
  `sniffImageMime()` (magic bytes) + `ALLOWED_UPLOAD_MIMES` +
  `MAX_UPLOAD_BYTES` (5 Mo) + rate-limit (20/h) + `assertNotMaintenance`.
  Persiste **immédiatement** `users.avatarUrl` (action directe, contrairement à
  une photo d'annonce enregistrée au « Enregistrer »).
- 🔨 `src/components/profile-form.tsx` : bouton « Importer depuis l'ordinateur »
  (composant réutilisable `PhotoUploadButton`, T-141) avec aperçu rond ; le
  champ URL reste disponible comme alternative. L'API met l'avatar à jour et le
  formulaire se synchronise (`router.refresh()`).

### 2) Commission par hébergement côté admin
- 🔨 `src/app/dashboard/properties/[id]/page.tsx` : récupère le rôle via
  `/api/auth/me` ; une carte **« Commission plateforme »** (taux %, 0–100)
  s'affiche **uniquement pour un admin** dans l'onglet Informations ; la valeur
  n'est envoyée au `PUT /api/properties/[id]` que si l'utilisateur est admin.
  Le backend refusait déjà la commission à un hôte (champ admin-only) — l'écran
  est désormais cohérent avec la règle.

### 3) Langue « arabe » non supportée
- 🔨 `src/components/admin/settings-panel.tsx` : retrait de l'option
  `🇸🇦 العربية` du sélecteur de langue par défaut (la locale UI réelle est
  `UiLocale = "fr" | "en"`).
- 🔨 `src/components/profile-form.tsx` : libellé explicite (FR/EN uniquement),
  suppression de la mention trompeuse « L'arabe reste en français ».
- Le hook `useDisplayPreferences` retombe déjà proprement sur « fr » pour toute
  valeur inconnue (défensif). Aucune migration de réglage (le schéma tolère
  encore « ar » côté données pour ne pas casser une base existante).

## Preuves runtime (DEV)

- Avatar : anonyme → **401** ; client → **200** `{url:"/uploads/….png"}` et
  `avatarUrl` persisté (vérifié via `/api/auth/me`) ; hôte → **200** ; fichier
  `.txt` renommé `.png` → **400** (magic bytes) ; fichier servi publiquement
  `GET /uploads/….png` → **200 image/png**.
- Commission : admin `PUT commissionRate:"18"` → **200**, `GET` → `18.00` ;
  hôte `PUT commissionRate:"2"` → **403**, la valeur reste `18.00` (non
  modifiable par l'hôte). Restaurée à `15` après test.
- Données de test nettoyées (avatars remis à `null` + fichiers supprimés,
  commission restaurée).
