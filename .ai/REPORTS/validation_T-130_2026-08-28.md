## Preuves d'exécution (▶️ dev, base Postgres)

### P1 — clôture / no-show hôte

Résa `confirmed`+`paid`, dates passées en base (l'API de création refuse les dates passées) :
- **No-show** : `PUT status="no_show"` (hôte, séjour passé) → **200**, `status=no_show`, **`loyaltyAwardedAt=null`**, wallet client **inchangé à 25,00** (aucune gratification).
- **Completed** : `PUT status="completed"` (hôte, séjour passé) → **200**, `status=completed`, **`loyaltyAwardedAt` posé** (récompense fidélité enregistrée).
- **Garde serveur** : `completed` **avant** départ → **400** « Le séjour ne peut être clôturé qu'après la date de départ » ; voyager → **400** « Un voyageur peut uniquement annuler ».
- **UI** : page détail hôte d'une résa `confirmed` → boutons **« Terminer le séjour »**, **« No-show »**, **« Annuler »**, **« Facture »** présents ; résa `completed`/`no_show` (terminal) → seules « Facture » (actions de transition masquées) ; un **voyageur** sur `/dashboard/*` → **307** (proxy edge), jamais exposé.

### P2 — parrainage exposé
- `GET /api/users/me/referral` → `{"code":"…"}` (200), anonyme → 401.
- Après fix : le bundle de `/mon-compte` contient **« Mon code de parrainage »** et l'appel `api/users/me/referral` ; l'ancien message « Le programme de parrainage n'est pas encore ouvert » a **disparu** du bundle.

### P3 — badge non-lus
- Cœur messagerie revérifié : envoi customer → `unreadByHost=1` ; réponse host → `unreadByUser=1` ; lecture → remis à 0 ; non-participant → 403.
- Le composant `UnreadMessagesBadge` est présent dans les bundles du header et des deux sidebars dashboard ; il réutilise `GET /api/conversations` (déjà filtré par participant), sans nouvelle route ni donnée exposée.

### P4 — photos édition
