### A2 — faux positif (vérifié à l'exécution, aucun code ajouté)
En relisant la route cron en entier, la fonction `expirePendingBookings()`
existe **déjà** dans `/api/cron/price-alerts` (appelée à chaque run) : elle
annule les `pending` dont `paymentExpiresAt < now`, annule l'intention de
paiement provider, décrémente l'usage promo, restitue le wallet et libère le
stock. Preuve d'exécution : réservation forcée `pending`/expirée →
`expiredPendingBookings = 1`, statut passé à `cancelled` / `failed` avec le
motif « Paiement non finalisé dans le délai ». Mon audit n'avait listé que les
fichiers cron sans voir que le sweep vit dans ce cron unique.

## A1 — Filtre de prix cohérent avec la devise d'affichage

- Nouvelle fonction partagée **`priceBoundToStorage(value, displayCurrency)`**
  dans `src/lib/i18n.ts` : convertit une borne saisie en FCFA vers l'EUR
  (devise de stockage). Sans devise / EUR / devise inconnue → valeur inchangée
  (historique, non-régression).
- `recherche/page.tsx` : le prédicat SQL normalise désormais le prix de chaque
  chambre en EUR (`base_price::numeric / CASE currency … taux`), avec les mêmes
  taux figés que l'affichage (`RATES_FROM_EUR`). Les bornes sont converties via
  `priceBoundToStorage`. Cast `::numeric` (sinon le driver infère `integer`
  depuis le 1er taux EUR=1 et rejette « 1.08 », erreur 22P02).
- Nouveau composant client **`SearchPriceFilter`** : champ caché
  `displayCurrency` (depuis `useDisplayPreferences`, XAF par défaut) + libellés
  dynamiques (« Prix max. (FCFA) ») à la place des placeholders « € ».

**Preuves d'exécution (page RSC `/recherche`)** :
- sans filtre : 8 logements ; `maxPrice=100` (EUR historique) : **3** ;
  `maxPrice=50000` sans devise : **8** (50 000 € ne filtre pas, historique
  préservé) ;
- `maxPrice=50000&displayCurrency=XAF` (≈76 €) : **0** ;
  `=80000 XAF` (≈122 €) : **6** ; `=100000 XAF` (≈152 €) : **8**.
- Tests unitaires : `50000 XAF ≈ 76 €`, aller-retour `89 € → XAF → EUR ≈ 89`.
