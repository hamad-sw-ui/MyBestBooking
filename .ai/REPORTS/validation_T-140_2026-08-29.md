## 3. Anomalie corrigée (T-140)

**Problème** : les dernières routes API admin retournaient le message d'erreur
zod **brut en anglais** sur une entrée invalide (ex. `Expected number, received
string`). Cela incohérait avec la politique d'interface 100 % française déjà
appliquée aux routes métier via le helper `frenchZodMessage`.

**Solution (sans régression)** : remplacer les `error.issues[0]?.message` /
`issues[0].message` par `frenchZodMessage(<err>)`, qui renvoie un message
français adapté aux types Zod attendus, en conservant le statut HTTP 400.

Fichiers modifiés :
- `src/app/api/admin/bulk/route.ts` (import + handler 400)
- `src/app/api/admin/providers/[provider]/route.ts` (2 handlers : POST create + PATCH update)
- `src/app/api/admin/settings/[key]/route.ts` (PATCH)
- `src/app/api/users/[id]/suspend/route.ts` (PATCH)

Aucune migration, aucune route nouvelle, aucun changement de contrat
(statut 400 conservé, seul le texte du message change).
