# Rapport de validation — T-173 (fiabilité bascule de langue)

- **Date** : 2026-09-01
- **Tâche** : T-173 (niveau **S**)
- **Résultat** : **CORRIGÉ (VALIDÉ)**

## Symptôme rapporté

Le sélecteur de langue (header/compte) était jugé « peu fiable » : après
connexion, des pages restaient partiellement dans l'ancienne langue.

## Cause racine

Cache de module `useDisplayPreferences` jamais invalidé après une
navigation SPA (`router.push`/`router.refresh` de login/register) : serveur
re-rendu dans la langue du compte, clients figés dans la langue anonyme →
UI mixte FR/EN jusqu'au prochain F5. Défaut secondaire : écriture locale
avant PATCH sans rollback en cas d'échec.

## Correctifs livrés

1. `use-display-currency.ts` : `DISPLAY_PREFS_EVENT` +
   `invalidateDisplayPreferences()` + hook abonné (re-résolution réactive) ;
   `resetDisplayPreferencesCache()` inchangé ; export additif
   `resolveDisplayPreferences()` (testabilité).
2. `login-client.tsx` / `register-client.tsx` : invalidation post-succès.
3. `language-selector.tsx` : rollback complet (état + stockage) si PATCH KO.
