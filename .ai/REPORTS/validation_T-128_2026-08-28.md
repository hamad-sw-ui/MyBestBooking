## ▶️ Preuves d'exécution réelle

**Route d'état**
- Maintenance OFF : `GET /api/maintenance-status` → `{"active":false}`.
- Activation (admin) `PATCH /api/admin/settings/security {maintenanceMode:true}` → 200 ; puis `GET /api/maintenance-status` → `{"active":true}`.
- La gate est bien présente dans le bundle servi (la page `/` référence `MaintenanceGate` et `/maintenance`).

**Comportement de la garde** (simulation équivalente à l'effet client, exécutée contre la **vraie** route d'état — Chromium headless indisponible dans le sandbox, téléchargement CDN bloqué) :

Maintenance **active** :
```
anonyme /            -> active=true  redirige=/maintenance
anonyme /recherche   -> active=true  redirige=/maintenance
admin   / (reste)    -> active=true  redirige=(aucune)
anonyme /maintenance -> active=true  redirige=(aucune)
anonyme /connexion   -> active=true  redirige=(aucune)
```
Maintenance **inactive** :
```
anonyme /            -> active=false redirige=(aucune)
anonyme /recherche   -> active=false redirige=(aucune)
admin   /            -> active=false redirige=(aucune)
```

**Protections existantes conservées**
- Écritures API bloquées en maintenance (`assertNotMaintenance` → 503) ; `POST /api/auth/login` reste **200** (anti-verrouillage) ; la gate ne s'applique pas aux admins ni aux pages d'auth.
- Gardes RSC `redirect("/maintenance")` toujours en place (navigation client / seconde couche).

## 🎯 Non-régression
- Maintenance OFF → route `active:false` → gate totalement inerte (le rendu du site est strictement identique ; la gate ne rend rien).
- Aucun contrat d'API existant modifié ; aucune migration.
- Un admin n'est jamais redirigé (il peut désactiver le mode) ; `/maintenance` et les pages de login ne bouclent pas.
- La gate ne bloque jamais le site si la sonde échoue (catch silencieux) ; la sécurité transactionnelle reste côté serveur (503).
