# Rapport de validation — T-167 (i18n vague 3)

- **Date** : 2026-09-01
- **Tâche** : T-167 (niveau **S**) — extraire les restes FR user-facing vers
  `ui-strings` + `useT`/`makeT` ; interpolation `.replace` / `.replaceAll`
  uniquement (`makeT` inchangé) ; SSR cookie `en` avant rechargement.
- **Résultat** : **VALIDÉ** — surface UI sur `t("key")`, catalogue **1354**
  clés FR=EN, garde-fou `i18n:check` **0 candidat**, SSR cookie `en` **prouvé**.

---

## 1. Périmètre livré

- Dictionnaire `src/lib/ui-strings.ts` : **1354** clés, mêmes clés FR et EN.
- Wiring `useT()` / `makeT()` sur auth, compte, messages, chrome dashboard,
  settings (hors placeholders d’exemples), bulk, analytics/billing, formulaires
  hôtes, widgets (promo, calendrier stop-sell, téléphone, parrainage, langue).
- SSR : `getServerLocale` (compte → header `x-ui-language` → cookies RFC
  `mybb-ui-language` + historique `mybb:ui-language` → réglage plateforme →
  `fr`) ; proxy tamponne `?lang=` / cookie → header sur `/`, `/recherche`,
  `/hebergement`, `/reservation`, `/bestrewards`, `/aide` (matcher public,
  `/reservation` reste **public**).
- Sélecteur anonyme : `persistUiLanguageClient` puis `?lang=` + cookies dual.
- Pays via `countryLabel` + clés `prop.country.*` (ex. Maroc / Morocco).

## 2. Non-régression

- `makeT` **non modifié** (pas d’interpolation interne).
- Aucune migration DB, aucun contrat API public retiré.
- Pages légales / centre d’aide déjà bilingues (T-162 / T-158) — non
  réécrites.
- Hors périmètre assumé (voir `KNOWN_LIMITATIONS.md`) :
  - placeholders d’exemple du panneau admin (`settings-panel`, adresse
    « 12 rue du Plateau… ») ;
  - PDF/HTML facture (`invoice`) ;
  - messages JSON d’API ;
  - termes neutres (ISO, OTP, codes devise, marque, « No-show » métier).
