# Validation T-141 — Bouton « Importer depuis l'ordinateur » pour les photos de propriété

- **Demande utilisateur** : lors de l'ajout ou du changement d'une photo d'un
  hébergement, disposer d'un bouton explicite qui ouvre le gestionnaire/sélecteur
  de fichiers de la machine.
- **Date** : 2026-08-29.
- **Branche** : `arena/01a042cf-mybestbooking`.
- **Type** : amélioration UX/accessibilité, additive (aucune migration, aucune
  route nouvelle — réutilise `POST /api/properties/upload` existant).

## Problème constaté

L'ouverture du sélecteur de fichiers de la machine **fonctionnait déjà** via un
`<input type="file">` natif, mais :
1. il s'affichait comme un champ de fichier générique (pas un vrai bouton
   « Importer » explicite et cohérent avec le design system) ;
2. dans la galerie d'**édition**, on pouvait seulement *supprimer* une photo ou
   la *définir comme principale* : il n'y avait aucun moyen de **remplacer
   directement** une image (il fallait la supprimer puis en ré-ajouter une, ce
   qui changeait l'ordre et perdait la position « principale »).

## Solution (sans régression)

- 🔨 Nouveau composant réutilisable **`src/components/photo-upload-button.tsx`**
  : un `<Button>` stylé qui déclenche un `<input type="file">` masqué
  (`inputRef.click()`). Props : `onFile(file)`, `accept`, `multiple`, `loading`,
  `variant`, `size`, `title`, `ariaLabel`. La valeur de l'input est réinitialisée
  après chaque sélection pour permettre de re-choisir le même fichier.
- 🔨 **Page de création** (`dashboard/properties/new/page.tsx`) : le champ natif
  est remplacé par le bouton « **Importer depuis l'ordinateur** » ; un bouton
  « **Changer l'image** » apparaît sous l'aperçu de la photo principale.
- 🔨 **Page d'édition** (`dashboard/properties/[id]/page.tsx`) :
  - bouton « **Importer depuis l'ordinateur** » en tête de l'onglet Photos ;
  - helper `uploadPhoto(file, replaceUrl?)` factorisé : si `replaceUrl` est
    fourni, l'URL de la vignette concernée est **remplacée en place** par la
    nouvelle (ordre conservé, et si c'était la photo principale le statut
    « principale » suit la nouvelle URL) ; sinon ajout en galerie comme avant ;
  - chaque vignette gagne une action « **Changer cette image** » (icône
    rafraîchir) à côté de « Définir principale » et « Supprimer ».

Aucun changement de contrat API : l'upload passe toujours par
`POST /api/properties/upload` (multipart, 5 Mo max, types MIME validés par
magic-bytes, réservé aux hôtes/admins).

## Preuves runtime

- ▶️ DEV (3000) :
  - `POST /api/properties/upload` (hôte, PNG valide) → **200** `{url:"/uploads/….png"}` ;
  - idem avec le cookie **client** → **403** (réservé hôte/admin) ;
  - `/dashboard/properties/new` → 200, `/dashboard/properties/[id]` → 200.
- ▶️ PROD (`next start` 3100, arrêté après test) : page de création rendue avec
  le bouton « Importer » (libellé + aria-label présents dans le HTML, HTTP 200).
- 🧹 Image PNG de test supprimée de `public/uploads/` ; réservation smoke
  supprimée ; compteur revenu à **32 réservations**.
