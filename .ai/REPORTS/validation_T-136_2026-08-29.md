# T-136 — Audit fonctionnel n°14 : auto-vote « utile » + code HTTP de l'inscription

Date : 2026-08-29 · Niveau : **L** · Additif, **aucune migration**, aucune table.

## Origine

Audit fonctionnel profond n°14 (espaces hôte/admin/client/anonyme testés en
réel : chambres/disponibilités/stopSell/plans tarifaires, machine à états des
réservations, modération d'avis, promos expirées/futures, wallet, achats

mineures corrigées ici.

## Corrections

### A1 — Auto-vote « utile » sur son propre avis (intégrité, sévérité faible)
- **Problème** : `POST /api/reviews/[id]/helpful` empêchait le double vote
  (unicité + 409) et limitait le spam, mais pas le vote sur **son propre**
  avis : un voyageur pouvait incrémenter lui-même le compteur d'entraide de
  son avis. Le bouton `ReviewHelpfulButton` ne savait pas non plus s'il
  s'agissait de l'avis du connecté.
- **Correctif** :
  - `src/app/api/reviews/[id]/helpful/route.ts` : la transaction sélectionne
    désormais `reviews.userId` ; si `review.authorId === user.id`, la route
    renvoie **400** « Vous ne pouvez pas marquer votre propre avis comme
    utile » (avant toute insertion de vote).
  - `src/components/review-helpful-button.tsx` : nouvelle prop `isOwn` ; quand
    `true`, le composant ne rend rien (`return null`) — le bouton n'est pas
    proposé à l'auteur (l'intégrité reste garantie côté serveur).
  - `src/app/(main)/hebergement/[slug]/page.tsx` : passage de
    `isOwn={review.userId === viewer?.id}` au bouton.

### A2 — Inscription d'un email existant → 409 (sémantique HTTP)
- **Problème** : `POST /api/auth/register` avec un email déjà utilisé
  répondait **400** au lieu de **409 Conflict** (convention pour une
  ressource existante). Le message était correct ; seul le code de statut
  était non-idéal.
- **Correctif** : `src/app/api/auth/register/route.ts` renvoie maintenant
  **409** sur la branche « compte existe déjà ». Les autres erreurs de
  validation restent en 400 (champ faible, format, etc.). Le front
  (`inscription/page.tsx`) teste `!response.ok`, donc le message d'erreur
  continue de s'afficher sans changement d'UX.
